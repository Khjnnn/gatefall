2. 플랫폼과 범위
- 제품은 Android/iOS 모바일 전용, 이번 실행 산출물은 Android APK다. PC 제품 UI, 키보드 안내, Windows 실행 파일/ZIP 제작은 작업에서 제외하라. PC의 Unity Editor·자동 검사·Android 에뮬레이터는 개발 도구로 계속 사용한다.
- 기존 가로 화면을 기본으로 휴대폰 터치에 최적화하라. iOS를 막는 불필요한 플랫폼 종속성을 피하되 Mac/Xcode 환경이 없으면 IPA 완료를 주장하거나 Android 작업을 중단하지 마라.
- 기존 첫 챕터 6작전을 다듬는 데 집중하라. 신규 챕터, PvP/협동, 길드, 가챠, 상점, 일일 퀘스트, 배틀패스, 광고/결제, 새 성장 트리나 재화를 추가하지 마라.

3. 단순한 게임 구성
- 핵심 루프: 작전 선택 → 짧은 준비 → 약 3분 방어 → 보상 → 다음 작전. 각성자 이동·자동 공격, 결계 방어, 타워 건설·강화, 재료를 소비하는 레시피 조합과 매 판 간단한 무작위 성장을 유지하라. 랜덤다이스 참고를 이유로 무작위 소환/주사위 시스템까지 별도로 얹지 마라.
- 메인 화면은 작전/성장/설정 정도로 정리하고, 첫 화면의 가장 뚜렷한 행동은 출전이어야 한다. 연구·각성자 성장의 중복 동선은 한 성장 화면으로 정리할 수 있다. 실험실·디버그·상세 수치표는 일반 플레이를 방해하지 않게 분리하라.
- 전투 HUD에는 결계 상태, 진행 상황, 필요한 재화와 조작만 남겨라. 이동 조이스틱 외 상시 액티브 스킬 버튼은 기본 1개를 목표로 정리하고, 타워를 선택하면 하나의 문맥 패널에서 건설/강화/조합을 처리하라. 겹치는 패널과 상시 전체 조합표를 없애라.
- 타워 종류·레시피를 더 늘리지 말고 기존 내용을 순차 해금하라. 첫 판에는 기본 배치와 강화, 이후 판에서 조합을 하나씩 가르쳐라. 인접 공명은 직관적인 보조 효과로 설명하고 별도의 관리 작업으로 만들지 마라.
- 세계관은 짧은 상황 대사와 환경 연출로 전달하라. 긴 설명을 읽어야 플레이할 수 있게 만들지 마라. 불필요한 중간 화면·중복 확인·보상 팝업을 줄여라.
- 단순화는 문구를 숨기는 데서 끝내지 말고 입력 수, 화면 전환 수, 동시에 판단해야 할 선택을 줄여라. 변경 시 기존 저장과 해금·보상·조합 거래의 일관성을 지켜라.

4. 디자인과 아트의 구체적 기준
- 먼저 현재 게임을 실제 실행해 스크린샷을 남기고, 문제를 전장 가독성/색/형태/여백/버튼 계층/피드백으로 구체적으로 진단하라. 그 뒤 한 가지 아트 방향을 정해 끝까지 통일하라.
- 방향은 휴대폰에서 선명하게 읽히는 스타일라이즈드 2D 현대 도시 판타지다. 낡은 도로·상가·방위대 장비와 검은 탑의 대비로 라온시를 표현하라. 배경은 절제된 중간 명도·낮은 채도, 아군 결계와 적의 위협은 구별되는 제한된 강조색을 사용하라. 어둡다는 이유로 전체를 검정/남색으로 뭉개지 마라.
- 기존 자산은 품질이 맞으면 재사용하고, 맞지 않으면 새로 생성하거나 제작해도 된다. 모든 에셋의 시점·광원·외곽선·재질·디테일 밀도·크기를 통일하라. 생성 이미지는 알파·외곽·축소 가독성을 확인해 게임용으로 정리하고 Unity에 실제 반영하라. 이미지에 UI 글자/버튼을 구워 넣지 마라.
- 과한 네온·블룸·그라데이션·유리 카드, 의미 없는 장식 테두리, 동일한 크기의 버튼 나열, 문서나 관리 대시보드 같은 화면을 피하라. 단순한 사각형과 원을 놓고 완성된 게임 아트라고 하지 마라.
- 제작 방식이나 새 이미지 개수를 품질로 평가하지 마라. 절차형 아트도 완성도가 맞으면 사용할 수 있지만, 기존 도형에 외곽선과 색만 바꾼 수준에서 멈추지 마라. 대표 전장과 메뉴를 실제 휴대폰 표시 크기로 축소해 실루엣, 명도 계층, 글자 크기, 시선 흐름을 점검하고 수정하라. 생성 도구를 쓸 수 없으면 사용했다고 주장하지 말고 가능한 제작 방식과 남은 품질 한계를 기록하라.
- 적의 길, 건설 지점, 결계, 플레이어, 적 종류가 휴대폰 크기에서 즉시 구분돼야 한다. 타워 역할과 강화·조합 결과는 색만 바꾸지 말고 실루엣·구조·공격 표현으로 구분하라.
- 건설·강화·조합·피격·보스 예고에는 짧고 일관된 애니메이션과 음향 피드백을 주되 전장을 가리지 마라. 일관된 아이콘·서체·간격 규칙을 사용하고 중요 버튼의 터치 영역은 48dp 상당을 목표로 하라.

5. 실행 순서
- 시작 전에 다른 도구가 수정 중인 파일이 있는지 확인하고 담당 범위를 분리하라. 같은 파일·Unity 프로젝트 빌드를 동시에 수정/실행하지 마라. 관련 파일과 저장을 보존하라.
- 먼저 유지/통합/숨김 또는 제거할 기능과 한 가지 디자인 방향을 짧게 기록하고 곧바로 구현하라. 사소한 선택마다 승인을 기다리지 마라.
- 남은 검증의 체크리스트를 완료하는 것만으로 디자인 목표를 달성했다고 판단하지 마라. 먼저 현재 작전 지도·대표 전장·강화/조합 패널을 직접 보고 가장 큰 시각적 문제 3개를 정한 뒤 실제 화면에서 개선하라. 동시에 새 스타일 시안을 여러 개 확장하지 말고 하나의 방향을 완성하라.
- 대표 전장 1개에서 배경·타워·적·HUD·터치 조작·강화·조합·결과까지 완성도를 맞춰 실제 플레이하라. 이후 같은 규칙과 자산 체계를 기존 6작전에 적용하라. 콘셉트 시안만 계속 늘리지 마라.
- 기존 코어가 쓸 만하면 유지하고 필요한 범위만 리팩터링하라. 겉모습만 덮어씌우거나 이유 없이 전면 재작성하지 마라. 단순화로 규칙이 바뀌면 기획·코드·관련 검사를 함께 갱신하라.

6. 완료 기준
- Android에서 작전 선택부터 준비·전투·강화·조합·승패·보상·저장·다음 작전까지 연결되어야 한다. 조합 가능한 작전과 보스전의 기존 실제 UI 완주 증거를 확인하고 변경 영향이 있는 부분을 재검증하라. 성장 화면 수정 시 구매/환급/재실행 복원도 검증하라.
- 이동과 UI 터치의 충돌, 조이스틱 해제, 다중 터치, 일시 정지/백그라운드 복귀, 안전영역과 다른 휴대폰 비율을 확인하라. 에뮬레이터 검사와 실제 휴대폰 검사를 구분하고 없는 기기에서 검증했다고 하지 마라.
- 관련 전투·저장·조합·입력 검사를 통과시키고 실제 렌더링과 APK 설치/실행을 확인하라. 자동 테스트 통과를 디자인 품질의 증거로 대신하지 마라. 전장·UI의 전후 비교는 실제 게임 화면으로 남겨라.
- 프레임 지연, 과도한 이펙트/할당을 확인하고 측정 환경과 결과를 기록하라. 성능을 측정하지 않았으면 수치를 만들어 쓰지 마라.
- 모바일 전용 Android 빌드 경로를 마련하고 업데이트된 APK, 실제 스크린샷, 변경 요약, 검증 결과와 남은 제한을 전달하라. PC 빌드를 성공 조건으로 요구하지 마라.
- 작업 중 HANDOFF_CLAUDE.md, README.md, 관련 기획과 progress.md를 실제 상태에 맞게 계속 수정하라. 과거 PC 산출물은 이력으로 구분하고 새 목표와 충돌하는 안내를 고쳐라.
- 중단하거나 인계할 때는 수정한 파일, 사용한 빌드와 검증 증거, 남은 문제, 다음 첫 행동을 기록하라. 계획·구현·실행 확인을 구분하고, 오래된 APK의 성공을 새 빌드의 검증으로 표기하지 마라.

성공의 기준은 기능의 수가 아니라, 처음 보는 사용자가 짧은 안내만으로 플레이하고 강화와 조합의 차이를 이해하며, 전장과 UI가 하나의 일관된 모바일 게임으로 느껴지는가이다. 위 완료 기준까지 개발하고 실제 검증한 범위와 남은 일을 정직하게 인계하라.
