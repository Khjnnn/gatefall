# Unity 6 PR 통합 검증 — 2026-11-05

## 범위

Unity 6000.6.7f1이 설치된 Windows에서 PR #1·#3의 전투 변경과 PR #2의 캔버스 HUD를 로컬 `codex/unity-pr-validation` 브랜치로 통합했다. main 병합은 하지 않았다. 기존 인수인계서·task_plan·progress는 수정하지 않았다.

이 검증은 사람의 재미 평가, 휴대폰 실기기 또는 iOS 검증이 아니다. 보호 에뮬레이터와 사용자 저장은 건드리지 않고 새 소유 AVD와 합성 프로필을 사용했다.

## 빌드와 검사

- Unity 6000.6 자체 패키지 해석·C# 컴파일·Android IL2CPP ARM64 빌드를 완료했다.
- 호스트 검사는 Windows PowerShell 7.6.5 / .NET 10.0.11에서 실행했다. 이전 작업자의 Linux pwsh 7.4.6 / .NET 8 결과와 실행 환경을 구분한다.
- 빌드 전 검사 전체, 할당 검사, 퇴화 전략 `-Enforce`를 통과했다. 계획 검토 도구도 별도로 `-Enforce`를 실행해 위반 0을 확인했다.
- 에디터 Play에서 F2로 도시·전투 준비/건설 메뉴·진행 HUD·성장 카드·결과 화면의 IMGUI/Canvas 경로를 전환해 확인했다. 에디터 전용 QA 저장 경로를 사용했고 임시 검증 코드는 제거했다. 에디터 결과 화면은 UI 확인용 패배이며 밸런스 근거가 아니다.
- v2 서명, ZIP 16KB 정렬과 ARM64 네이티브 라이브러리 3개의 ELF LOAD 16KB 정렬을 통과했다.

검증용 통합 APK는 정식 새 버전 번호를 발급하지 않은 **0.27.36/code116 후보**다.

- 경로 `Builds/Android/Gatefall-pr123-canvas.apk`
- 크기 111,212,558바이트
- SHA256 `5b58fcfdd97631e3c5d3793c09ad9001996dde4405d305052b28c6e72b2ea741`

분홍색 문제가 있던 이전 후보는 별도 파일로 보존했으며 전달본으로 사용하지 않는다. 기존 버전 APK도 보존했다.

1-7에서 충분한 재화를 보유한 채 11번째 건설을 눌렀을 때 상한 안내가 표시되고 10기를 유지했다. 1-10은 180초를 넘겨 남은 적을 정리한 뒤 승리했다. 업데이트 전후 합성 저장 324바이트가 동일했으며, 8회 승리 후 각각 새 보상 ID·마핵 2·PendingRun 해제를 확인했다. 합성 프로필의 마핵은 340→356이고 기존 42별·성장 0·연구 0·편성 135를 유지했다. 전부 재도전이므로 첫 클리어 보상이나 새 해금 검증으로 확대하지 않는다.

1-14는 141.20초에 창+봉인을 뇌격으로 조합하고 소모된 봉인 자리에 붕괴를 보충했다. 이후 10기를 채운 상태에서 강화한 뇌격+붕괴의 종결 레시피가 활성화되는 것을 확인했다. 실제 종결 생성 입력 전에 전투가 종료되어 **종결 생성·10기 상태의 조합 성공은 미검증**이다. `seal-at-cap`·`seal-refill`이라는 이름의 캡처도 실제 내용은 결과 화면이며 성공 근거로 사용하지 않는다.

이 실행은 LIVE 메뉴를 검토하느라 모델보다 첫 조합과 후속 보강이 늦었다. 150초 임계의 세 번째 카드는 Resume 좌표 입력과 겹쳐 정체를 기록하지 못했다. 첫 빛창·두 번째 사거리만 확인했다. 입력은 본 QA에서 발생했으며 외부 입력으로 분류하지 않는다. 카드 3회·승리·보상·원장은 별도로 기록했다. 일반 1-14는 보스 작전이 아니므로 bossDefeated=False가 정상이다.

1-8은 QA 준비 스크립트의 정규식 전달 문제로 건설 입력이 비어 있었으며, 실제 첫 건설은 31.8초다. 초반 피해와 이 구매 지연을 분리해 기록했다. 스크립트를 문자열 분리·개수 검사 방식으로 수정했다. 1-9의 첫 준비 배치도 도시 화면에서 호출됐으나 시작 전에 확인하고 올바른 전투 준비 화면에서 다시 배치했다. 이 시점에는 전투가 시작되지 않았다. 캡처 파일명보다 실제 화면·구매 원장을 우선한다.

상세 원시 자료는 git 제외 경로 `TestResults/pr123-*`, 화면은 `Docs/QA/v050/pr123-*`에 남겼다. `TestResults/pr123-verify-evidence.ps1`은 새 게임을 실행하지 않고 실제 8개 결과·가격별 구매 내역·보상 ID·저장·설치 해시·ELF 검사 결과를 대조해 통과했다. 최종 집계는 `pr123-delivery-consistency.json`, 카드 관찰은 `pr123-cards-observed.json`이다. 결과 화면의 한국어·별·보상·버튼은 2400×1080·1920×1080·1280×720에서 확인했으며, 모든 메뉴의 전 해상도 검사를 뜻하지 않는다.

마지막 결과·지도·앱 콜드 재실행 후 합성 저장 324바이트의 SHA256은 모두 `b07417097c32f25f1785d2c69b53e3b12341238f3eef76838d3ef09d5b0fee6e`로 같다. 재실행 도시 화면에서도 356마핵·기존 42별을 확인했다. `pr123-relaunch-consistency.json`이 이 범위의 근거다.

## 남은 검증과 설계 한계

- 일반 1-7~1-14는 이번 APK에서 모두 완주했다. 모든 작전·위기·계정 성장·상위 조합 경로 전부를 Android에서 검사한 것은 아니다.
- 최적화된 창 단독·계정 무성장 계획도 모델에서 1-7~1-14 모두 3별이다. 성장 투자와 혼합 편성, 어려운 조합을 상위 공략에 요구하려면 적 역할과 보상 대비 비용의 추가 설계가 필요하다. 근거 없이 이번 검증에서 능력치를 바꾸지 않았다.
- 10기 상한은 PR #3에 포함된 정책이다. 사용자가 원한 많은 타워의 전투 참여와의 절충은 사람 플레이로 확인할 필요가 있다.
- HUD의 매 프레임 문자열 생성과 가변 슬롯 이동 문제, 저장 v3·규칙 검사 분리 등 인수인계의 후속 항목은 이번 검증으로 해결된 것이 아니다.
- Android 시작 진단과 포커스 전환 Surface 로그, 에디터 종료 시 JobTempAlloc 진단의 원인·실기기 영향은 확정하지 않았다. 오류 전체가 0이라고 주장하지 않는다.
- 고정 후보 앱 PID 6953의 시작부터 8회 전투·리사이즈·지도까지 기록에서는 AssetPackManager 1줄·EGL 협상 4줄 후 ES3.1 생성, 첫 PERF 이후 Surface 135줄·그 외 E/F 0·Fatal 서명 0·패키지 ANR/Crash 이벤트 0을 관측했다. `pr123-diagnostics.json`과 원문을 보존했다. HOME·크기 변경이 포함되어 휴대폰 성능 벤치마크로 사용하지 않는다.

## 종료 상태

소유 `GatefallPRUnityQA/emulator-5666`의 QEMU 25604·런처 26840은 Normal 우선순위 복원 후 정상 종료했고 프로세스 0·절대 경로·재분석 지점을 검사해 디스크를 정리했다. 별도 앱 PID 필터 logcat 클라이언트 36036도 명령행 소유권을 확인한 뒤 종료했다. 보호 5556/5558과 보호 경로에는 입력·종료·삭제를 보내지 않았다.

전용 폴더에는 다른 핸들에 잠긴 작은 로그 `stdout.log` 11,802바이트와 `stderr.log` 41바이트만 남았다. 사본을 보존했으며, 공유 ADB 서버나 다른 프로세스를 종료해 강제로 해제하지 않았다. `TestResults/qa-cleanup-pr123.json`의 `delayed-log-removal` 상태를 후속 작업자가 확인할 수 있다. 테스트 에뮬레이터가 실행 중이라는 뜻은 아니다.

로컬 작업 브랜치는 `codex/unity-pr-validation`이다. 수정 코드와 본 문서는 각 PR의 후속 커밋으로 보존하며 main 병합 판단과 실제 사람·실기기 검증은 별도다.
