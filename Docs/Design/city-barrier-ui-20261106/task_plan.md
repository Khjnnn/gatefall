# 도시 결계 UI 적용

## 목표
gatefall-style v1.0.0을 현행 건설·강화·조합 UI에 적용하고 공통 렌더 경로, 터치 영역, 게임 규칙과 저장을 보존한다.

## 단계
1. 현재 브랜치·변경·스킬·빌드/QA 기준 확인 — 완료
2. 프로젝트 내부 토큰 기준과 UI 표면·상태·정보 위계 적용 — 완료
3. 프로젝트 검사·Unity 폰트/렌더 검증·Android 후보 빌드 — 완료
4. 독립 QA 기기의 실제 건설·강화·조합 화면/입력·저장 검증 — 완료
5. 전달본·캡처·실제 검증 범위 기록 — 완료
6. 사용자 피드백 반영: 무광 표면·단색 선형 심벌·강화/조합과 판매의 위계 재설계 — 완료
7. 새 토큰 대비·한국어·변경된 클릭 영역과 Unity/Android 검증 — 완료
8. 독립 Android에서 새로운 건설·강화·조합 UI 확인 — 완료
9. 세련된 개선안의 실제 캡처와 APK 전달 — 완료
10. 사용자 제공 Pinterest·LAYERLAB의 실제 시각 자료와 현재 에셋 구조 조사 — 진행 중
11. Gatefall 맞춤 UI·소품·타워·FX의 독자 스타일 제작 가능성과 제작 규격 제안 — 대기
12. 스타일 검토용 시안과 근거·적용 우선순위 전달 — 대기

## 오류
- 초기 병렬 출력이 길어 도구 응답 일부가 잘렸다. 후속 조회는 필요한 범위로 나눈다.
- 제한 환경의 CIM 프로세스 조회와 adb 서버 연결이 거부됐다. 실제 QA 전 호스트 실행으로 소유 상태를 확인한다.
- verify-source와test-mobile을 같은PowerShell프로세스에서 연속 호출해Add-Type 중복 로드가 났다. 프로젝트 표준처럼 각 검사를 별도pwsh프로세스로 실행한다. 소스/메타와6코어 보존 검사는 이미 통과했다.
- 첫Unity컴파일에서 CampaignHud의 CardAccent 공통 호출을 놓친 오류 확인. 얇은 역할 표시 헬퍼를 복원한다. 이미 통과한 모델/전략 검사는 재사용하고 소스/Unity 단계부터 재실행한다.
- Unity빌드 후ADB서버가재시작되어첫QA설치가device-not-found로실패. 실제QEMU/ADB상태와재연결을확인한뒤설치를다시진행한다.
- Cua의AX Home버튼은분리도구창이주창범위밖이어서좌표검사에거부됨. 실제캡처를갱신하고해당도구창캡처영역으로지정한다.
- QA중예상과다른추가건설/2배속/카드진행관찰. 사용자직접조작여부를비동기질문하고추가입력/QA파일변경/종료는답변전보류한다. 소스·검증기록정리는계속한다.
- 사용자가 직접 플레이 중이 아님을 확인하고 QA를 재개했다. 초기 작전1-3에서 최종 APK의 건설·강화·부족·활성 조합→재료 선택→Lv1 생성까지 다시 직접 확인했다. 앞선 예상 밖 진행의 원인을 단정하지 않는다.
