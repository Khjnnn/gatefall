# 2챕터 대표6작전 제작·검증 브리프

후속 추가 기획: [2챕터 전체22작전·적/보스/성장 계획](GATEFALL_CHAPTER2_FULL_PLAN_2026-11-06.md). 이 문서의 첫6개 구현 단위와 선행 검증 계약은 유지한다.

상태:10챕터 기획의 **다음 구현 단위**. 신규 스테이지/수치/아트는 아직 구현하거나 플레이하지 않았다. [전체 전략](GATEFALL_10_CHAPTER_STRATEGY_2026-11-06.md)과 함께 읽는다. 현재0.28.11 UI후보의 Android검증을 먼저 끝내며, 이 문서 작성 때문에 사용자5692를 조작하거나 미검증 전달물을 설치하지 않는다.

## 1. 첫6작전

처음 두 작전은 새 챕터의 적응 구간이다. 기존4종으로 통과할 수 있어야 하며 새 타워/성장 구매를 진입 조건으로 걸지 않는다.2-2클리어 뒤 산탄 후보를 해금하고2-3에서 쓰임을 소개한다. 정확한 적 수/능력치/시각/가격은 데이터 기반 프로토타입으로 정한다.

| 작전 | 맵/진입 | 차별화된 판단 | 제안 파형/도구 | 검증할 실패 원인 |
|---|---|---|---|---|
|2-1 다솜 남문|긴 서쪽/짧은 남쪽,2진입·24~26지점|입구 하나 집중보다 남쪽 우선 보강|6웨이브/3~3.5분 후보. 기존창+붕괴로 적응|새 챕터 입구부터 레벨벽, 남쪽 길 사거리 밖 지점|

2-6은 정예 점검전이며 탑2의 봉인 보스는2-22다. 보스 없는2-6에 기존 `Index==5` 판정을 복사해 보스 처치를 요구하면 안 된다.2-1~2-6은 각기 다른 경로 원형을 우선 제작하고, 미술 색이나 좌우 반전만으로6개를 채우지 않는다. 한 결계/고정 도로를 유지하며 호위·복수 방어대상·자유 미로 건설은 추가하지 않는다.

### 2-1 파형 초안

1. 서쪽 일반 묶음으로 공격 구간을 읽게 한다.
2. 남쪽 빠른 무리로 짧은 전선 보강을 소개한다.
3. 서쪽 밀집 무리와 남쪽 소수 정예를 시간차로 보낸다.
4. 남쪽 짧은 두 묶음/서쪽 여유로 강화와 새 건설을 선택하게 한다.
5. 서쪽 장갑 묶음 뒤에 일반 적, 남쪽에는 작은 빈 구간을 둔다.
6. 두 전선의 복합 파형으로 마무리하되 첫 도착 시점을 완전히 겹치게 하지 않는다.

새 입구·적 종류·물량은 웨이브 예고와 도로가 일치해야 한다. 적 수를 매 파형 무조건 증가시키지 않는다. 정예/공성 묶음은 수가 적어도 압박이 커질 수 있다. 선택 호출은 현재 방식처럼 남은 적과 겹칠 수 있음을 알리고, 보급을 중복 지급하지 않는다.

v3 후보는 `SchemaVersion,StageProgressById,HeroGrowthById,ResearchById,LoadoutIds,TutorialSeenIds,StorySeenIds,PendingRun,LastRewardRun`을 분리한다. 상세 직렬화 포맷은 구현 설계에서 정하되 아래 계약을 먼저 고정한다.

- 이전v1/v2를 읽고 원본 백업/새 파일 검증 뒤 원자적으로 교체한다. 실패 시 원본과 메모리 계정을 유지하고 저장 실패를 안내한다. 사용자 실제 파일에 직접 시험하지 않는다.
- 금액·성장·연구·일반/위기별·첫클리어·편성·음소거·과거보상/ID·Pending의 모든 필드를 대조한다. 보상 재계산이나 과거단계 재구매를 하지 않는다. 스키마/손상 검사와 현재의 해금 규칙 검사를 분리한다.
- 정상 완료/패배/포기/중복 완료/쓰기 실패·재시도/완료 직전 종료를 검사한다. 완료 저장이 성공하기 전 새 보상을 두 번 지급하지 않는다. 실패한 신규 해금이 옛 진행을 무효화하지 않아야 한다.
- v3를 만든 뒤 구형APK로의 진행 호환을 자동 보장하지 않는다. 백업을 남기되 서로 다른 버전이 같은 저장을 덮어쓰는 경로를 피한다. 신규 버전의 진행을 버리고 옛v2로 조용히 되돌리지 않는다.
- StageID/모드/시드 기록은 재현 관측용이다. 현재는 전체 전투 스냅샷을 저장하지 않으므로 시드만 넣었다고 중간 전투 복원을 제공한 것으로 해석하지 않는다.
- 타워/영웅ID를 바꾸거나 기존enum을 재배열하지 않는다. 새 콘텐츠는 새ID를 추가하고 구ID 매핑을 보존한다. 의도치 않은32비트 편성 상한이나 배열 인덱스 접근을 검사한다.
- 도시의 `1-숫자` 고정 표기,6개씩 나눈 작전 목록 페이지, 챕터/전체 별 합계도 데이터와 연결한다. 챕터 선택과 목록 페이지 이동을 구분하고 미구현 지역을 출전 가능한 것으로 표시하지 않는다. 신규 챕터 화면도 현재 공통 UI 스타일을 사용하며 챕터마다 별도 조작법을 만들지 않는다.

## 3. 제작과 검증 순환

각작전은 `짧은 브리프→경로/지점→명시 파형→편성/경제→모델→Android 실제 입력/완주→관측 기록→수정` 순으로 끝낸다.6개를 기계적으로 만든 뒤 한꺼번에 수치 조정하지 않는다.

### 모델 표본

대표6작전×3시드×권장아래/권장/위성장×창중심/혼합/강화중심/조합후보충×일반/위기 = **432조건 후보**다. 이는 앞으로 수행할 검증 예산이며 이미 실행한 숫자가 아니다. 빠른 파일럿은 선택2작전×2시드×아래/권장×혼합/조합=16조건부터 시작한다. 실패한 후보를 전체432에 자동 확대하지 않는다. 기존 정합 결과는 재사용하되 변경한 데이터가 다른 전투의 재사용 근거를 깨지 않는지 먼저 확인한다.

공통시드·카드/영웅 입력 정책·선택 전 상태·구매 규칙·예산 상한을 맞춘다. 같은 상한을 같은 실제 지출로 표시하지 않는다. 실제 구입 시각/레벨·동시 기수/정리시간·마지막 출현 시각/최저 결계·갈래별 누수/사격·실효피해·감속/남은 재화·촉매를 기록한다. 조합 재료의 소모 전 사격ID와 최종 살아 있는 타워 수를 구분한다.

### 채택·반려 기준

- 적절한 계정 성장에서 최소 두 편성/투자 정책의 승리 대안이 있어야 한다. 모델의 최적계획 한 개가 사람의 쉽게 찾는 공략이라는 뜻은 아니다.
- 추천아래 성장의 후반 압박과 추천 성장의 개선을 보되, 낮은 성장을 모든 시드 무조건 패배로 만드는 목표는 두지 않는다. 과성장이 있어도 완전 무판단 배치가 모든 어려운 작전3별로 수렴하면 역할/파형을 재검토한다.
- 초반2-1/2-2는 적응 여유를 둔다. 이후 정예·방향·조합 공백에서 판단이 필요하도록 한다. 보통 신규 적/규칙을 한 전투에 하나씩 소개한다.
- 봉인은 사격 수만이 아니라 강한 적의 감속 시간/접근/결계 피해 감소를 본다. 종결은 같은 실제 지출의 재료 유지·창/붕괴 보강과 비교한다. 정리속도와 방어 이득을 따로 보고 어려운 조합의 상황별 이득을 확인한다.
- 예산 내에서 재료Lv2→1차강화→종결→빈자리 보충이 적법하게 가능해야 한다. 조합 완성 전에 사실상 승패가 결정되거나 완성 직후 전투가 끝나면 파형/가격을 재검토한다. 부족한 재화를 검사에서 지우거나 무료 가격 보정하지 않는다.
- 영웅의 몸막기/방벽으로 적 경로를 영구 봉쇄하는 정책도 선택 표본으로 검사한다. 공성의 저지 무시와 영웅 사망/부활의 현재 역할을 유지하고, 일반 적만 무한히 묶으면 시간 제한이 없어서 생기는 소프트락도 확인한다.
- 모든 실제 지점은 도로와 겹치지 않고 기본 도구로 대응 가능한 구간을 가져야 한다. 경로 정적 덮음과 실제 선행 처치에 의한 유휴를 분리한다. 방어 후방 보험은 존재할 수 있으나 미리보기/실전에서 사거리 밖인 지점을 양산하지 않는다.

### Android/모바일

각작전 실제 완료·실패/재시도·강화/조합·카드/일시정지 복귀·보상/지도/콜드 저장을 확인한다. 작은1280/1920과긴2400 실제안전영역에서 메뉴/먼지점/HUD·경고를 확인한다. 경고·HP·투사체/사망효과가 역할색과 길을 덮지 않아야 한다.

대량 적·지원 범위·관통/공중 후보는 모바일 프레임·메모리·발열의 실기기 검사가 필요하다. HOME나녹화/해상도 전환이 섞인 에뮬레이터 PERF를 휴대폰 성능 벤치마크로 쓰지 않는다. 사람 플레이·청감/iOS를 못 봤으면 보류라고 기록한다.
