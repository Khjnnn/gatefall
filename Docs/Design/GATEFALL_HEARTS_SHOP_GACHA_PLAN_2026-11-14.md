## 1. 벤치마킹

Random Dice: Defense(111%)에서 가져올 틀이다. 스토어 소개와 공개된 플레이 정보로 확인한 것과, 직접 확인하지 못한 것을 나눠 적는다.

| Random Dice의 틀 | 확인 | Gatefall에 옮긴 것 |
| --- | --- | --- |
| 재화 둘: 골드(게임으로 벌어 강화에 씀)와 다이아(유료) | 스토어 상품에 다이아 묶음이 있다 | 마핵(기존)과 결정(신규) |
| 주사위 카드를 모아 같은 카드가 쌓이면 골드로 등급을 올린다 | 공개 공략에서 확인 | 결계주 카드와 결계주 등급 (6절) |
| 뽑기는 카드 상자다. 계정 단계가 오를수록 상자 내용이 좋아진다 | 공개 공략에서 확인 | 보급 상자. 도달한 장에 따라 내용이 늘어난다 |
| 일일 상점에서 골드로 카드를 직접 산다 | 공개 공략에서 확인 | 일일 상점 (5절) |
| 시즌 패스: 무료 줄과 유료 줄 | 스토어 소개와 상품 목록에서 확인 | 방어 기록 패스 (7절) |
| 보상형 광고를 여러 자리에 둔다 | 리뷰 사이트에서 "광고가 잦다"는 평 | 보상형만, 네 자리, 하루 한도 (4절) |
| 한정 묶음 상품(전설 선택 묶음 등) | 스토어 상품 목록에서 확인 | 시작 묶음, 장 완료 묶음 |

| 광고 룰렛: 하루 정해진 횟수, 확률표 팝업이 있다 | APK 식별자(`AdsRoulettePanel`, `AdsRoulettePercentagePopup`, `AdsRouletteDailyReset`) | 무료 상자를 광고 룰렛으로 바꾼다 (4절) |
| 일일 광고 보상과 "광고 보기" 일일 임무 | APK 식별자(`ReceiveDailyAdsReward`, `DailyMissionWatchAds`) | 일일 임무에 광고 1회 보기를 넣는다 (7절) |
| 일일 상점을 광고로 새로 고친다(횟수 한도) | APK 식별자(`StoreDailyResetCountByAds`) | 그대로 (4·5절) |
| 상점에 기간 한정 확률 상승 일정과 약관 패널이 있다 | APK 식별자(`ShopDicePercentUpSchedule`, `ShopTermsPanel`) | 상자 화면에 확률표·약관 버튼을 둔다. 확률 상승 행사는 넣지 않는다(서버 없이 일정을 믿을 수 없다) |
| 계정: 게스트로 시작해 구글 로그인·Play 게임즈로 연결한다 | APK 식별자(`OnClickAccountLink`, `LinkWithPlayGamesCoroutine`, `GoogleSignIn`, `ISavedGameClient`) | Play 게임즈 서비스 연동 (8절). Random Dice는 Firebase 서버에 저장하고, Gatefall은 서버 없이 저장된 게임만 쓴다 |
| 광고 중개는 AppLovin MAX에 Google Mobile Ads를 얹는다 | APK 라이브러리 목록 | 처음에는 AdMob만 쓴다. 중개는 수익이 생긴 뒤에 본다 |
| 세로 화면, 아래 탭 다섯 개, 가운데가 전투 | 스토어 스크린샷 | 가로 화면에 맞춰 아래 탭 줄로 옮겼다 (2절) |

APK 근거는 2026-10-26의 정적 분석(`C:/dev/rea_project/random_dice_work`, 버전 9.5.5)에서 뽑은 이름들이다. 게임 코드 본문은 보호 장치로 암호화돼 있고 수치 표는 서버에서 받으므로, 확인된 것은 "그런 기능이 있다"까지이고 횟수·시간·가격·확률 같은 숫자는 알 수 없다.

가져오지 않는 것: 실시간 대전과 협동(서버가 필요하다), 판 안의 무작위 소환(Gatefall은 자리를 골라 짓는 게임이다), 등급이 오를수록 끝없이 강해지는 구조(+10% 한도를 둔다).

Gatefall의 지금 상태에서 설계에 영향을 주는 사실은 넷이다.

- 마핵이 남는다. 성장·연구를 전부 사도 300 안팎인데 44작전 첫 승리 보상 합계가 1,558이다. 3-8 완료 검증 저장에 1,394가 남아 있었다.
- 저장은 기기 안 파일 하나(`raon-profile.sav` v3)이고 서버가 없다.
- 광고·결제·계정 패키지가 프로젝트에 없다.
- APK는 개발용 Debug 서명이다.

원칙은 1판과 같다. 광고는 보상형만, 돈을 쓰지 않아도 44작전 3별 가능, 광고가 안 떠도 막히지 않음, 전투 규칙과 기존 진행은 그대로.

```
┌───────────────────────────────────────────────────────────────────────────┐

│ │ 12단계 ▓▓▓░░    │                                        │ 광고 3/3   │ │

│ ┌ 선택 작전 3-7 ──┐                                        │ 2/5        │ │

│  [ 상점 ● ]  [ 결계주 ● ]  [[ ▶ 작전 출전  ♥1 ]]  [ 성장 ]  [ 작전 지도 ]  │
└───────────────────────────────────────────────────────────────────────────┘
```

- **아래 탭 줄**: 다섯 칸이고 가운데가 출전이다. 왼쪽부터 상점, 결계주(카드·편성), 출전, 성장(헌터·연구), 작전 지도. 지금의 카드 네 칸(`MobileHud.Home.cs` 55~58행)을 대체한다. 설정은 오른쪽 위 톱니로 옮긴다.
- **위 줄**: 각성자 초상과 계정 단계, 하트(타이머와 여분), 마핵, 결정, 우편, 설정. [+]는 상점의 해당 탭으로 간다.
- **왼쪽**: 패스 진행 띠와 선택 작전 패널. 패널을 누르면 작전 지도로 간다.
- **오른쪽 세로 줄**: 광고 룰렛, 일일 임무, 출석. 받을 것이 있으면 알림 점(●)을 붙인다.
- 출전 버튼에 드는 하트 "♥1"을 적는다. 하트가 없으면 색이 바뀌고 누르면 부족 창이 뜬다.

### 늘릴 수 있게

- 탭 줄과 세로 줄은 목록 데이터로 그린다. 항목을 더하면 칸이 는다. 탭이 일곱을 넘으면 좌우로 밀고, 세로 줄은 넷을 넘으면 접는다.
- 기준 폭 960(4:3)에서는 탭의 설명 글자를 숨기고 아이콘과 이름만 남긴다.
- 해금은 지금 규칙을 따른다. 편성은 1-10 뒤, 상점과 결계주 카드는 1-3 뒤에 열린다. 잠긴 탭은 조건을 적어 흐리게 둔다.
- 배치는 전투 HUD와 같은 12개 화면으로 겹침을 검사한다(`Tests/HudOcclusionChecks.cs`의 화면 목록 재사용).

## 3. 하트

### 규칙

- **기본 하트**는 최대 5개이고, 5개 미만일 때 **15분에 1개** 찬다. 다 쓰고 75분이면 가득 찬다.
- **여분 하트**는 따로 쌓이고 최대 999개다. 시간으로는 차지 않는다. 보상·광고·상점으로 받은 하트는 기본 하트가 가득 차 있으면 여분으로 들어간다. 999를 넘는 분은 받지 못하므로, 넘칠 때는 받기 전에 알린다.
- 표시는 "♥ 3/5 · 12:40"이고 여분이 있으면 "+17"을 붙인다.
- **작전 출전 1회에 1개**를 쓴다. 일반·위기·재도전 모두 같다. 기본 하트부터 쓰고(충전 타이머가 바로 돈다), 기본이 0이면 여분을 쓴다.
- 하트는 출전을 눌러 준비 화면으로 들어갈 때 빠진다. 저장이 `PendingRun`을 기록하는 순간과 같은 저장 한 번에 넣는다.
- 진행 중이던 출전을 이어 들어갈 때는 다시 쓰지 않는다. **패배와 포기는 돌려주지 않는다.**
- 결과 화면의 "다시"와 "다음 작전"은 새 출전이므로 1개를 쓴다.

### 클리어 보상 하트

패배 때 돌려주지 않는 대신, 처음에는 하트가 모자랄 일이 없게 한다.

| 조건 | 여분 하트 |
| --- | ---: |
| 첫 접속 | 기본 5개 |
| 1장 작전 첫 승리 (1-1~1-14) | 작전마다 +10 |
| 2장 작전 첫 승리 (2-1~2-22) | 작전마다 +3 |
| 3장 이후 작전 첫 승리 | 작전마다 +2 |
| 장의 마지막 작전 첫 승리 | 추가 +10 |
| 처음으로 3별 | 작전마다 +1 |

1장을 끝내면 여분 하트가 150개 쌓인다. 한 번도 실패하지 않으면 1장에서 쓰는 하트는 14개다. 하트가 실제로 모자라기 시작하는 것은 2장 후반 이후, 재도전과 위기 작전을 돌 때다.

기존 플레이어는 업데이트할 때 이미 깬 작전의 보상을 소급해서 받는다(최대 999).

### 하트가 모자랄 때

| 선택 | 결과 | 한도 |
| --- | --- | --- |
| 광고 보기 | 하트 +1 후 바로 출전 | 하루 10회 |
| 결정으로 충전 | 결정 30으로 하트 5개 | 없음 |
| 기다리기 | 다음 충전까지 남은 시간을 보여 주고 닫는다 | — |

광고가 준비되지 않았으면 광고 버튼을 "광고 준비 중"으로 비활성화한다.

### 시간 계산

기기 시계를 쓴다. 저장에 "마지막으로 본 시각(UTC)"과 "다음 충전 기준 시각"을 두고, 앱을 켜거나 홈으로 돌아올 때 지난 시간만큼 한 번에 채운다. 시계가 마지막으로 본 시각보다 과거면 충전하지 않고 기준만 지금으로 옮긴다. 시계를 앞으로 돌려 채우는 것은 서버 없이는 막지 못한다(8절). 하루 한도는 기기 현지 날짜가 바뀔 때 초기화한다.

### 구현 틀

- Google Mobile Ads Unity 플러그인의 보상형 광고만 쓴다. 광고 단위는 자리마다 하나.
- Core에는 SDK를 넣지 않는다. Core에 "광고 보상 요청·결과" 인터페이스만 두고, Presentation에 AdMob 구현과 가짜 구현(성공 / 실패 / 준비 안 됨)을 둔다. Core 검사는 지금처럼 Unity 없이 돈다.
- 보상은 SDK의 보상 지급 콜백을 받았을 때만 준다. 지급과 한도 차감은 저장 한 번으로 함께 기록한다.
- 광고는 홈에 들어올 때 미리 불러 둔다.
- 개발·QA 빌드는 구글의 공개 테스트 광고 단위 ID만 쓴다. 에뮬레이터 QA는 가짜 구현으로 보상 흐름을 검증한다.
- 동의 창(UMP)을 첫 실행에 붙인다.

### 결제

- Unity IAP(Google Play 결제). 결정과 묶음은 소모성, 자동 수령권은 비소모성, 패스는 시즌마다 사는 소모성이다.
- 결제 완료 통지를 받고 저장에 기록한 뒤 구매를 확정한다. 저장 전에 앱이 죽으면 다음 실행 때 미확정 구매를 다시 받아 지급한다. 같은 주문 번호는 한 번만 지급한다.
- 결정은 유상분과 무상분을 따로 세고, 쓸 때는 무상분부터 쓴다.
- 비소모성 상품은 설정 화면의 "구매 복원"으로 되찾는다.

## 6. 뽑기: 보급 상자와 결계주 등급

### 틀

Random Dice처럼 "뽑기 = 카드 상자, 성장 = 같은 카드를 모아 등급 올리기"로 한다. 결계주 자체는 지금처럼 작전 진행으로 해금하고, 상자에서는 **이미 해금한 결계주의 카드**와 마핵, 가끔 외형이 나온다.

- 결계주마다 등급 1~6이 있다. 같은 결계주 카드를 정해진 수만큼 모으고 마핵을 내면 등급이 오른다.
- 등급 하나에 그 결계주의 피해 **+2%**. 등급 6에서 **+10%**이고 그 위는 없다.
- 등급 6을 넘겨 모인 카드는 마핵으로 바뀐다.
- 조합 결과(뇌격, 종결 등)는 판 안에서 조합으로 만들지만, 카드 등급은 계정에 붙어 있다가 그 결계주가 전장에 생기면 적용된다.

| 등급 | 필요한 카드 (누적) | 마핵 | 보너스 |
| --- | ---: | ---: | ---: |
| 1 → 2 | 4 | 10 | +2% |
| 2 → 3 | 10 | 20 | +4% |
| 3 → 4 | 20 | 40 | +6% |
| 4 → 5 | 40 | 80 | +8% |
| 5 → 6 | 80 | 160 | +10% |

### 희귀도와 확률 (출발값)

결계주 15종을 넷으로 나눈다.

| 희귀도 | 결계주 | 일반 상자 | 고급 상자 |
| --- | --- | ---: | ---: |
| 일반 | 창, 봉인, 붕괴, 방벽, 표식 | 79% | 50% |
| 희귀 | 산탄, 관통, 뇌격, 파쇄, 중력 | 18% | 35% |
| 영웅 | 관측창, 추적, 탄막, 쇄도 | 2.7% | 12% |
| 전설 | 종결, 외형 | 0.3% | 3% |

- 일반 상자는 카드 3장과 마핵 5~15, 고급 상자는 카드 8장과 마핵 20~40이다. 카드 한 장마다 위 확률로 희귀도를 정하고, 그 안에서 해금한 결계주 중 하나를 같은 확률로 고른다.
- 아직 해금하지 않은 결계주의 카드는 나오지 않는다. 그 희귀도에 해금한 결계주가 없으면 한 단계 아래로 내린다.
- **천장**: 고급 상자 30개 안에 전설 카드가 없으면 30개째에 전설 한 장이 들어간다. 횟수는 저장에 남고 화면에 보인다.
- 장을 넘길 때마다 상자의 카드 수가 한 장씩 는다(일반 3 → 4 → 5, 고급 8 → 9 → 10).

### 힘의 한도와 게이트

- 보너스는 결계주 종류당 최대 +10%이고, 성장·연구와는 곱해지지 않고 더해진다.
- 빌드 전 난이도 게이트는 지금처럼 **등급 1 계정**으로 돌린다. 돈을 쓰지 않아도 깨진다는 보증이다.
- 여기에 "전 결계주 등급 6 계정에서도 창 봇이 3-3 이후를 세 시드 모두 3별로 깨지 못한다"를 더한다. 등급이 판단을 대신하면 안 된다. 이 게이트가 깨지면 배율이 아니라 등급 보너스를 줄인다.
- 위기 작전은 등급 보너스를 끄고 기록한다. 위기 별점은 실력 기록으로 남긴다.

### 표시 의무

- 상자 화면에 희귀도별·결계주별 확률표와 천장 규칙을 보는 버튼을 둔다.
- 한국은 2024년 3월 22일부터 확률형 아이템의 확률 표시가 의무다. 최근 3년 연평균 매출 1억 원 이하는 예외지만, 구글 플레이가 구매 전 확률 공개를 따로 요구하므로 처음부터 표시한다. 유상으로 직접 사는 것뿐 아니라 간접적으로 유상인 것도 대상이므로 마핵으로 여는 일반 상자도 표시한다. 광고에는 "확률형 아이템 포함" 문구가 필요하다. 세부 표시 항목은 출시 전에 문화체육관광부 해설서 원문으로 확인한다.
- 확률표는 코드의 확률 데이터에서 직접 만든다. 검사에서 희귀도별 합이 100%인지와 10만 회 모의 결과가 표와 맞는지를 본다.

## 7. 일일 임무, 출석, 방어 기록 패스

| 기능 | 내용 | 보상 |
| --- | --- | --- |
| 일일 임무 | 여섯 개: 작전 3회 승리, 3별 1회, 조합 2회, 위기 작전 1회, 상자 1개 열기, 광고 1회 보기 | 임무마다 패스 점수와 마핵, 전부 끝내면 일반 상자 |

시즌의 시작과 끝은 기기 날짜로 정한다(서버가 없으므로). 시즌 번호는 고정된 기준일에서 4주 단위로 계산한다. 패스는 1~2단계 구현에서 뺄 수 있는 첫 번째 후보다.

## 8. 서버 없이 가는 구조와 구글 계정 연동

### 서버가 없어서 생기는 한계

| 한계 | 대응 |
| --- | --- |
| 기기 시계를 돌려 하트·출석·일일 상점을 당길 수 있다 | 시계가 과거로 가면 충전을 멈춘다. 앞으로 돌리는 것은 감수한다 |
| 저장 파일을 고칠 수 있다 | 지금의 체크섬을 유지한다. 완전히 막지는 못한다 |
| 결제 영수증을 기기에서만 검증한다 | 주문 번호를 저장에 남겨 중복 지급을 막는다. 위조 영수증은 구글 플레이 쪽 검증에 기댄다 |
| 순위표·대전처럼 남과 비교하는 기능은 믿을 수 없다 | 넣지 않는다 |

혼자 하는 게임이라 조작의 피해가 본인에게 한정된다는 점이 서버 없이 갈 수 있는 근거다.

### 구글 계정 연동: Play 게임즈 서비스

자체 서버 없이 구글 계정에 진행을 묶는 방법은 **Play 게임즈 서비스(PGS) v2의 저장된 게임**이다. 저장 데이터가 구글 쪽에 보관된다.

- **로그인**: PGS v2는 앱이 뜰 때 자동으로 로그인을 시도한다. 게임은 그 결과만 받아 온다. 실패하거나 Play 게임즈 프로필이 없으면 기기 저장만으로 그대로 논다. 로그인은 강제하지 않는다.
- **클라우드 저장**: 저장 파일 하나를 스냅샷으로 올린다. 스냅샷 한도는 3MB이고 지금 저장은 1.2KB 안팎이라 여유가 크다.
- **올리는 때**: 작전 결과가 저장된 뒤, 결제·상자 개봉 뒤, 홈으로 돌아올 때. 전투 중에는 올리지 않는다.
- **내려받는 때**: 앱을 켤 때와 설정의 "클라우드에서 불러오기".
- **충돌**(기기 저장과 클라우드 저장이 다를 때)은 다음 순서로 푼다.
  1. 한쪽 커밋 해시가 다른 쪽의 최근 조상 해시 이력에 있으면 새 쪽을 쓴다. 일련번호·시각·진행만으로는 조상 관계를 판단하지 않는다.
  2. 갈라졌으면 두 저장의 요약(도달 작전, 별, 마핵, 결정, 마지막 플레이 시각)을 보여 주고 고르게 한다.
  3. 어느 쪽을 고르든 **유상 결정과 비소모성 구매는 두 저장의 주문 번호 목록을 합쳐 다시 계산한다.** 고르는 과정에서 산 것이 사라지지 않게 한다.
- **기기를 바꿀 때**: 새 기기에서 같은 구글 계정으로 자동 로그인되면 클라우드 저장을 찾아 불러올지 묻는다.
- **덤**: 같은 SDK로 업적(장 완료, 전 작전 3별 등)을 붙일 수 있다. 순위표는 위 표의 이유로 넣지 않는다.

필요한 준비: Play Console에서 Play 게임즈 서비스 설정, 저장된 게임 사용 설정, 서명 인증서 지문 등록, 테스터 계정. Unity 쪽은 Play Games Plugin for Unity v2(자동 로그인은 v11 이상)를 쓴다. Core에는 "클라우드 저장 읽기·쓰기" 인터페이스만 두고 Presentation에 PGS 구현과 가짜 구현을 둔다.

한계: 클라우드 저장도 기기에서 만든 파일을 올리는 것이라 조작을 막는 수단은 아니다. 목적은 기기 교체와 재설치 때의 복구다. iOS에는 PGS가 없어서 iOS를 낼 때는 Game Center·iCloud로 따로 만들어야 한다.

### 저장 형식

v4로 올린다. 더하는 것: 저장 일련번호, 결정(유상·무상), 기본·여분 하트, 충전 기준 시각, 마지막으로 본 시각, 날짜별 한도 사용량, 결계주별 카드 수와 등급, 가진 외형, 천장 횟수, 일일 상점 목록과 날짜, 임무·출석·패스 진행, 지급한 주문 번호 목록, 비소모성 구매, 소급 지급 여부.

v3 저장을 읽으면 새 필드를 기본값으로 채우고 클리어 보상 하트를 소급한다. 진행·마핵·성장·연구는 그대로다. 업데이트 전후 기존 필드 보존은 지금까지와 같은 방법으로 검증한다.

## 9. 이용 등급

**등급은 고르는 것이 아니라 나온다.** 구글 플레이에서는 콘솔의 등급 설문(IARC)에 답하면 내용에 따라 국가별 등급이 매겨진다. 한국에서는 이 결과가 게임물 등급으로 쓰인다. 등급을 가르는 것은 폭력·선정성·사행성 같은 **내용**이고, Gatefall은 사람이 아닌 괴물을 쏘는 판타지 전투라 전체이용가나 12세 이용가가 나올 가능성이 높다. 15세로 올릴 요소는 지금 없다. 확률형 아이템과 광고가 있다는 것만으로 등급이 올라가는지는 설문 결과로 확인해야 한다.

등급과 따로 정해야 하는 것이 **대상 연령**이다. 콘솔에서 앱이 겨냥하는 나이대를 고르는데, 13세 미만을 포함하면 가족 정책이 적용된다. 광고는 아동용으로 인증된 것만 쓸 수 있고, 계정 로그인과 데이터 수집이 크게 제한된다. 보상형 광고·뽑기·구글 계정 연동을 모두 쓰려는 이 기획과 맞지 않는다.

| 항목 | 추천 |
| --- | --- |
| 이용 등급 | 설문 결과를 따른다. 전체이용가나 12세 예상 |
| 대상 연령 | 13세 이상 (아동을 대상에 넣지 않는다) |
| AdMob 설정 | 아동 대상 아님, 광고 콘텐츠 등급은 게임 등급에 맞춰 제한 |

즉 "전체이용가 등급"은 가능하지만 "아동을 대상으로 하는 앱"으로 내는 것은 권하지 않는다. 등급이 전체이용가로 나와도 대상 연령을 13세 이상으로 두는 것은 가능하다. 스토어 문구와 그림이 아동을 겨냥한 것처럼 보이면 구글이 대상 연령을 다시 판단할 수 있다.

## 10. 단계와 검증

| 단계 | 내용 | 외부 계정 |
| --- | --- | --- |
| 1 | 저장 v4, 하트 규칙과 클리어 보상, 홈 화면 탭 줄, 하트 부족 창(가짜 광고) | 필요 없음 |
| 2 | 결계주 카드·등급, 보급 상자와 확률표, 일일 상점, 일일 임무·출석 (결정은 무료 지급분만) | 필요 없음 |
| 3 | 방어 기록 패스 | 필요 없음 |
| 4 | Play 게임즈 서비스 로그인과 클라우드 저장, 스토어용 서명·AAB | Play Console |
| 5 | AdMob 연결, 동의 창 | AdMob |
| 6 | Unity IAP, 결정·묶음 판매 | Play Console 상품 등록 |

1~3단계는 지금 방식으로 끝까지 검증할 수 있다.

- Core 검사: 하트 충전 시간, 시계 되돌림, 여분 999 한도, 클리어 보상 소급, 한도 초기화, 상자 확률·천장·미해금 처리, 등급 비용과 +10% 한도, 저장 왕복, 충돌 병합(주문 번호 합치기).
- 난이도 게이트 두 가지(등급 1 계정, 등급 6 계정).
- 화면 겹침 감사에 홈 화면 추가.
- 전용 에뮬레이터에서 합성 저장으로 하트 0 → 부족 창 → 보상 → 출전, 상자 개봉, 등급 올리기, 재실행 뒤 저장 일치, v3 → v4 업데이트.

4~6단계는 계정과 스토어 설정이 있어야 끝까지 검증된다. 내부 테스트 트랙에 올려 테스터 계정으로 확인한다.
